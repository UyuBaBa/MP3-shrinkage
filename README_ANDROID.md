# MP3 Уровень — версия для Android

Приложение выравнивает громкость всех mp3 в выбранной папке (вместе с
подпапками) и складывает результат в новую папку с той же структурой.

## Чем оно отличается от версии для ПК

На ПК громкость менялась перекодированием через ffmpeg. На Android так нельзя:
ffmpeg там нет, а **MP3-кодировщика в Android не существует вообще** — системный
MediaCodec умеет mp3 только декодировать. Поэтому здесь применён метод самой
утилиты mp3gain:

| | ПК (Tkinter) | Android (Kivy) |
|---|---|---|
| Как меняется громкость | перекодирование `-af volume` | правка поля `global_gain` в кадрах |
| Качество | падает (пересжатие) | **не меняется вовсе** |
| Размер файла | меняется | остаётся байт в байт |
| Теги, обложка | переносятся ffmpeg | вообще не затрагиваются |
| Точность | любая | шаг 1.5 дБ (промах ≤ 0.75 дБ) |
| Чем измеряется уровень | ffmpeg `volumedetect` | системный декодер Android |
| Режим LUFS (EBU R128) | есть | нет (нужен ffmpeg) |

Шаг 1.5 дБ — не ограничение реализации, а устройство формата: `global_gain`
это показатель степени, один его шаг равен 1.5 дБ. Настоящий mp3gain работает
ровно так же.

## Файлы

- `main.py` — интерфейс Kivy: выбор папки, шкала, уровень, прогресс, журнал.
- `job.py` — обход папки, расчёт усиления, запись результата.
- `mp3gain.py` — разбор кадров MPEG Layer III и правка `global_gain`.
- `probe.py` — измерение уровня: MediaCodec на телефоне, ffmpeg на ПК.
- `buildozer.spec` — параметры сборки APK.

## Сборка APK

Buildozer работает только под Linux, поэтому из Windows собирать нужно либо
на серверах GitHub, либо через Docker/WSL.

### GitHub Actions — основной способ

В репозитории уже лежит `.github/workflows/build-apk.yml`. Порядок такой:

```powershell
cd "D:\Cetochka2\LLM Projects\MP3 shrinkage"
git init
git add .
git commit -m "MP3 Уровень: версии для ПК и Android"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/mp3-level.git
git push -u origin main
```

Репозиторий на GitHub создайте заранее (кнопка **New repository**, без
README и .gitignore — они уже есть здесь). После пуша сборка стартует сама;
следить за ней на вкладке **Actions**. Первый прогон идёт 30–50 минут
(качаются Android SDK и NDK), последующие — минут пять благодаря кэшу.

Когда прогон закончится, откройте его страницу и скачайте артефакт
**mp3level-apk** внизу — внутри `mp3level-1.0-arm64-v8a-debug.apk`.
Запустить сборку повторно без пуша можно кнопкой **Run workflow**.

Если репозиторий приватный — всё работает так же, минуты Actions для
приватных репозиториев расходуются из бесплатной квоты.

### Docker — если собирать у себя

Из папки `android`:

```powershell
docker run --rm -v "${PWD}:/home/user/hostcwd" -v "buildozer_home:/home/user/.buildozer" kivy/buildozer android debug
```

Первая сборка скачивает Android SDK/NDK — примерно 4–6 ГБ и 30–60 минут.
Повторные сборки занимают минуты: всё скачанное лежит в томе `buildozer_home`.
Готовый файл появится в `android/bin/mp3level-1.0-arm64-v8a-debug.apk`.

### WSL

```bash
sudo apt update && sudo apt install -y python3-pip openjdk-17-jdk zip unzip \
    autoconf libtool pkg-config zlib1g-dev libncurses-dev libtinfo6 cmake
pip3 install --user buildozer cython
cd /mnt/d/Cetochka2/LLM\ Projects/MP3\ shrinkage/android && buildozer android debug
```

### Установка на телефон

APK не подписан для магазина — это debug-сборка, ставится вручную:
скопируйте файл на телефон и откройте его, разрешив установку из этого
источника. Либо через ADB: `adb install -r bin/mp3level-1.0-arm64-v8a-debug.apk`.

## Как пользоваться

1. При первом запуске приложение попросит **доступ ко всем файлам**
   (Android 11+). Без него не видно папок с музыкой. Выдайте разрешение
   в открывшихся настройках и вернитесь в приложение.
2. «Выбрать папку» — кнопки «Память», «Музыка», «Загрузки» ведут к обычным
   местам; можно спуститься в любую подпапку и нажать «Выбрать эту папку».
3. Шкала: «mp3gain (89 дБ)» — привычные единицы mp3gain, «RMS (dBFS)» —
   цифровая шкала, где 89 дБ соответствует -18 dBFS.
4. «Начать». Прогресс и подробности по каждому треку видны на экране,
   результат — в новой папке внутри выбранной.

Замер требует полного декодирования трека, поэтому первый проход по большой
папке идёт заметно дольше самой правки громкости (она мгновенная).

## Замечания

- Папка результата помечается файлом `.mp3_normalizer_output`, и следующий
  запуск её пропускает — можно делать несколько версий в одной папке.
- Галочка «Не допускать клиппинга» ограничивает подъём так, чтобы пик не
  превысил -0.3 dBFS.
- Если у трека уже нужный уровень, он просто копируется.
